# OPERATIONS.md — 운영 절차 (기획안 §8 Phase 5.4)

> 대상: `.github/workflows/crawl.yml`(워크플로 이름 `weekly-crawl`)이 도는 일일 갱신.
> 전제: 이 파이프라인에는 사람이 실행하는 복구 경로가 없다(AGENTS.md §1 확정, 2026-07-27). 아래는 전부 **확인 절차**이며, 사람의 조작은 확인이 끝난 알림 이슈를 정리하는 것뿐이다.

## 1. 일일 갱신 확인

### 1.1 실행 이력

```
gh run list --workflow crawl.yml --limit 7
```

```
completed	success	weekly-crawl	weekly-crawl	main	workflow_dispatch	30946829337	4m2s	2026-08-04T20:12:55Z
```

열은 status · conclusion · 런 이름 · 워크플로 · 브랜치 · 이벤트(`schedule` 또는 `workflow_dispatch`) · run ID · 소요 · 생성 시각(UTC)이다.

판별 지점 둘.

- **발화 시각** — 지정 슬롯 시각과 실발화 시각은 다르다. 실측 지연 창은 `AGENTS.md` §1이 단일 기재다. 창 안의 지연은 GitHub cron의 정상 동작이라 드롭으로 판정하지 않고, 창을 넘겨도 그날 `schedule` 런이 없으면 슬롯이 드롭된 것이다.
- **conclusion** — `success`는 런이 끝났다는 뜻이지 데이터가 갱신됐다는 뜻이 아니다. 조기 종료는 확보분을 커밋하고 exit 0으로 끝나므로 여기서도 `success`로 찍힌다.

### 1.2 데이터 갱신 여부

```
git log -1 --date=iso-strict --format='%h %ad %s' -- public/data
```

제목 형식은 `data: daily update <날짜> (<모드>)`다. 출력의 커밋 시각(오프셋 동반)이 그날 슬롯이면 갱신됐다. 커밋이 없으면 수집이 산출물을 바꾸지 못한 것이고, 앱은 직전 데이터를 그대로 서빙한다(무커밋 계약).

### 1.3 자동 알림

```
gh issue list --label auto-alert --state open
```

워크플로가 만드는 이슈는 제목 접두 4종이다 — `주간 수집 조기 종료` · `산출물 가치 미달` · `배포 화면 기준일 불일치` · `주간 수집 실패`. **억제 단위는 접두가 아니라 그날 제목 전체**(접두 + KST 날짜)라, 열린 이슈를 닫지 않아도 다음 날 같은 종류의 알림은 뜬다. 조건이 지속되면 날마다 1건씩 쌓이고 그 쌓임 자체가 "며칠째 같은 상태"라는 신호다. 닫는 자동화는 두지 않는다(사람이 연 이슈까지 닫힌다 — AGENTS §9 2026-08-05).

## 2. quick·full 모드 판별

슬롯 2개는 실행 여부가 아니라 **모드**를 가른다. 이 표가 갱신 슬롯·모드 분기의 서술 단일 기준이고, 기계 원천은 `.github/workflows/crawl.yml`의 `on.schedule`이다.

| cron (UTC) | KST | 모드 | 수집 범위 |
|---|---|---|---|
| `0 18 * * 6` | 일 03:00 | full | 전량 — 상세 요청 포함 |
| `0 18 * * 0-5` | 월~토 03:00 | quick | `--window 7 --no-detail` |

full이 주 1회인 이유: 요청 수가 로봇탐지 임계에 닿아 매번 조기 종료한다. quick은 매각기일 창을 좁히고 상세를 생략해 요청 수가 임계를 크게 밑돌아 매일 돌려도 닿지 않는다. 실측 요청 수와 임계 관측치는 같은 `on.schedule` 주석에 있다.

런 하나의 모드는 게이트 스텝 `실행 슬롯 판정`의 출력 한 줄로 확정한다.

```
gh run view <RUN_ID> --log | grep -F "직전 수집" | tail -1
```

```
crawl	실행 슬롯 판정	KST 2026-08-05 · 슬롯 'workflow_dispatch' · 모드 quick · 직전 수집 2026-08-03T19:58:42+09:00
```

`슬롯` 자리가 `workflow_dispatch`면 스케줄이 아닌 두 경로 중 하나다. **dispatch 런을 사람의 수동 실행으로 단정하지 않는다** — 방문자가 리프레쉬 탭을 눌러도 같은 이벤트가 찍힌다.

| dispatch 경로 | 일으키는 주체 | mode |
|---|---|---|
| 리프레쉬 탭 | 방문자 — `POST /api/refresh`가 서버에서 dispatch를 대신 호출(`src/app/api/refresh/route.ts`) | 항상 `quick`(코드 고정, 입력값 없음) |
| 수동 실행 | 작업자가 Actions 화면·`gh workflow run`으로 직접 | 입력값 `mode`(선택지·기본값은 crawl.yml `workflow_dispatch.inputs.mode`) |

리프레쉬 계약(쿨다운·경량 모드·실측)은 `AGENTS.md` §1이 단일 기재다. 커밋 제목 꼬리의 `(quick)`·`(full)`도 게이트가 정한 모드와 같은 값이다.

산출물만 보고도 갈린다 — quick은 상세를 생략하므로 `public/data/meta.json`의 `detailCoverage.requested`가 0이고 기일 이력이 전량 역산(`historySource.backcalc`)이다. full은 `historySource.real`이 채워진다.

## 3. 크롤 실패 대응

완전 실패한 날은 커밋이 없고, 앱은 직전 데이터와 그 수집 시각으로 동작하며, 다음 날 슬롯이 그대로 이어받는다. 사람이 하는 일은 이슈를 읽고 원인을 확인하는 데서 끝난다.

| 증상 | 워크플로 동작 | 사람이 할 일 |
|---|---|---|
| 세션 취득 실패 등 완전 실패 | job 안에서 재시도 창(`BUDGET_SEC`)이 남는 동안 재시도하고, 소진되면 exit 1·무커밋. 정기 슬롯은 matrix 시도가 뒤이어 **새 러너(=새 IP)** 로 다시 돈다(런 하나에 job이 여럿인 이유). 수동·리프레쉬는 1회차로 끝낸다 | `주간 수집 실패` 이슈에서 중단 사유 확인 |
| 로봇탐지·요청 예산 소진 | 조기 종료로 강등, 확보분만 커밋·배포 | `주간 수집 조기 종료` 이슈 확인 — 물건 데이터는 정상이고 기일 이력 정밀도만 낮다 |
| 산출물이 방문자 가치 기준 미달 | 배포는 막지 않고 이슈로 표면화 | `산출물 가치 미달` 이슈 확인 후 4절로 로컬 재현 |
| 커밋·배포는 됐는데 방문자 화면이 그 기준일을 말하지 않음 | 배포는 막지 않고 이슈로 표면화 | `배포 화면 기준일 불일치` 이슈 확인 — 로컬 재현은 `npx tsx scripts/verify-deployed-date.ts` |

재실행은 절차가 아니다. 같은 실패가 반복되면 원인은 코드 또는 상대 사이트에 있고 처방은 코드 수정이다. 파이프라인 코드를 고친 직후에 한해 `workflow_dispatch` 1회를 당일 돌린다 — 복구가 아니라 실전 등가 검증이다(AGENTS §1 단서·§9 2026-07-30).

## 4. 데이터 가치 게이트 확인

```
node .claude/hooks/data-value-gate.mjs --check
```

출력 예시(값은 실행마다 다르다 — 읽을 것은 꼬리의 `위반 N건`이다).

```
산출물 가치 게이트 — 기준 2026-08-16 · 총 1000건 · 미경과 기일 4일 · 원천 최종 기일 2026-08-21 · 직전 대비 신규 18건 · 0건 시도 1개 · 위반 0건
```

위반이 있으면 요약 아래에 `[R1] …` 형식으로 규칙 번호와 사유가 한 줄씩 붙고 exit 1이다. **규칙(R1·R2·R3·R5)의 정의와 임계는 게이트 코드 `.claude/hooks/data-value-gate.mjs`가 단일 원천**이며, 각 규칙 블록의 주석이 판정 근거를 말한다 — 이 문서는 임계를 옮겨 적지 않는다. (별도 도움말 모드는 없다. 인자를 무엇으로 주든 `--check`와 같은 채점이 돈다.)

판정 기준 시각은 실행 시각이 아니라 `meta.crawledAt`이라, Actions가 만든 이슈를 며칠 뒤 로컬에서 재현해도 같은 결과가 나온다.
