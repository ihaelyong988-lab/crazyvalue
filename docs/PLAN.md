## 0. 이 문서의 사용법 (트리거 프로토콜)

1. 주인님이 **"앱개발 시작하세요"**, **"앱사이트 개발해줘"** 등 개발 착수 취지의 지시를 하면(문구 불문), 에이전트는 추가 질문 없이 §8 실행 계획의 Phase 0부터 순차 수행한다.
2. 각 Phase는 `완료 기준(DoD)`의 기계 검증과 **§13 개발 필수 규칙 점검**을 통과해야 종료되며, 종료 시점마다 커밋·푸시하고 배포 URL과 함께 1줄 보고한다. 미통과 시 다음 Phase 진입 금지.
3. 중단 후 재개 시 §8의 체크박스 상태를 확인하고 이어서 실행한다.
4. 유일한 사전 조건은 §12의 계정 인증 2건(주인님 1회 수행)이다. 그 외 모든 결정은 본 문서에 이미 확정되어 있으며, 실행 중 모호함이 생기면 §8.0 공통 실행 규약의 폴백을 따른다.

## 1. 네이밍 (주인님 확정) — CrazyValue · 미친가치

**미친가치(CrazyValue)** — 유찰 2회 물건의 최저매각가격은 감정가의 49%(30% 저감 법원) ~ 64%(20% 저감 법원)다. 물건의 가치는 그대로인데 가격만 내려갔다. 이 앱이 파는 것은 "경매 정보"가 아니라 **"가치 대비 가격이 비정상으로 벌어진 물건만 골라 보여주는 큐레이션"** 이며, 이름이 그 가치제안을 1초 안에 전달한다.

### 1.1 병용 표기 규범 (전 산출물 공통)

| 맥락 | 표기 |
|---|---|
| 문서·보고 첫 등장 | **CrazyValue(미친가치)** 병기, 이후 문맥에 맞게 어느 쪽이든 사용 |
| 앱 헤더 워드마크 | **미친가치** (주) + **CrazyValue** (보조, 소형 로마자) |
| PWA manifest | name `미친가치 CrazyValue` · short_name `미친가치` |
| 저장소·프로젝트·도메인 | `crazyvalue` (로마자 소문자 단일어) → `crazyvalue.vercel.app` |
| 코드 내 키·식별자 | `crazyvalue.*` (localStorage) · `CrazyValueBot` (크롤러 UA) |
| 픽 배지 | 앱 내 `미친가치 픽` / 문서 병기 시 CrazyValue Pick |

### 1.2 카피 규칙 (컨셉 DNA 정합)
- "미친"은 **브랜드명과 픽 배지에서만** 사용한다. 본문 문장에서는 수식어로 쓰지 않는다(과장 수식어 금지 원칙 유지 — 문장은 단정형 컨설팅 톤).
- 구 가명 "반값경매"(v2.0, 에이전트 작명)는 폐기한다. 다만 "감정가의 반값 아래"라는 수치 사실은 미친가치 픽의 공개 기준으로 승계한다(§2.2).

## 2. 제품 정의

### 2.1 한 줄 정의
전국 법원경매 물건 중 **2회 이상 유찰된 초저가 물건만** 모아, 지역·금액·용도 3번의 탭으로 찾아보는 휴대폰 전용 앱(PWA) — **CrazyValue(미친가치)**.

### 2.2 컨셉 코어 — "덜 보여주는 큐레이션" + 3가지 가치 신호
경쟁자는 물건 수만 건을 다 보여주고 선별을 사용자에게 맡긴다. 미친가치는 반대로 **유찰 2회 이상만** 수집해 "이미 골라진 목록"을 준다. 그 위에 가치를 계산 없이 인지시키는 신호 3개를 얹는다.

| 신호 | 정의 | 화면 |
|---|---|---|
| 할인율 | `1 − 최저가/감정가` — 저장된 가격 비율(`priceRatio`)에서 파생되는 사실값 | 카드·상세에 "감정가 대비 −51%" |
| **미친가치 픽** | 최저가가 감정가 대비 판정 기준 이하로 내려온 물건에 부여하는 배지 — 임의 점수가 아니라 검증 가능한 사실 기준이고, 기준은 앱 안내에 공개한다. **판정식 단일 기준 = `AGENTS.md` §2 도메인 불변식**(파생 계산이라 저장 필드가 없다) | 리스트·상세 카드 배지 · `/list?pick` · `/guide`. 홈 진입점은 2026-07-22 철회(§4.3-① 철회 기록) |
| 유찰 이력 타임라인 | 회차별 최저가 하락 서사 — "왜 이 가격인가"의 근거 | 상세 시그니처 블록 |

### 2.3 문제와 해법
| 기존의 문제 | 미친가치의 해법 |
|---|---|
| 법원경매정보 사이트는 PC 중심, 검색 조건이 전문가용으로 복잡 | 모바일 온리, 필터 3개(지역·금액·용도)로 단순화, 타이핑 0회 |
| 유료 경매정보 서비스는 월 수만 원대, 초보에게 과잉 | 무료, 회원가입 없음 |
| 물건이 수만 건이라 "싼 물건"을 골라내는 눈이 필요 | **유찰 2회 이상만 수집** + 미친가치 픽 — 선별을 앱이 대신함 |
| 관심 물건의 기일·재유찰을 직접 챙겨야 함 | 관심함에서 D-day와 상태 변화를 추적 |

### 2.4 "실시간"의 해석 (원안 모순 해소)
원안의 "실시간 정보"와 "매주 일요일 3시 업데이트"는 충돌한다. 본 기획은 **"언제 어디서나 즉시 조회 가능(가용성)"** 으로 해석을 확정하고, 데이터 신선도는 **매일 03:00 KST 갱신**으로 한다(2026-08-05 주인님 확정 — 원안의 주 1회에서 상향. KST 월~토는 경량 수집, 일요일은 전량 수집). 신뢰 확보를 위해 모든 화면 상단에 수집 시각을 상시 표기한다(§4.3-① 기준일 바).

### 2.5 타깃 사용자
| 페르소나 | 상황 | 핵심 요구 |
|---|---|---|
| 경매 입문 실수요자 | 내 집·상가를 시세 이하로 마련하고 싶으나 경매 용어가 낯섦 | 쉬운 화면, 용어 설명, 안전 고지 |
| 소액 투자자 | 출퇴근 틈에 지역·금액대로 훑어보고 싶음 | 빠른 필터, 관심함, D-day |
| 경매 학습자 | 유찰 물건의 가격 흐름을 관찰하며 공부 | 기일 이력 타임라인 |

### 2.6 MVP 성공 지표 (측정 정의)
근거 없는 목표 수치는 두지 않는다. 첫 4주는 베이스라인 측정 기간으로 하고, 이후 목표를 설정한다. (Vercel Analytics)
- 홈화면 설치 수 / 주간 재방문율 / 방문당 관심등록 전환율 / 검색→상세 도달률 / **공유 클릭률**(OG 카드 효과 측정 — Hobby 플랜이 커스텀 이벤트를 미지원하면 OG 유입 페이지뷰로 측정 정의 대체)

## 3. 시장·경쟁 (사전 조사 요약)

> 착수 시점 재검증 전제의 사전 조사 요약이다. (조사 상세는 §3.3 함의 참조)

### 3.1 경쟁 구도
| 서비스 | 과금 | 성격 | 미친가치와의 차이 |
|---|---|---|---|
| 지지옥션 | 유료(월 구독) | 전문가용 종합 경매정보 | 권리분석 등 전문 기능 중심, 초보에게 과잉·고가 |
| 탱크옥션 | 유료 | 전문가·준전문가용 | 상동 |
| 스피드옥션 | 유료(저가형) | 가성비 경매정보 | 여전히 PC 중심 UI |
| 옥션원(구 두인경매) | 부분 무료 | 무료 검색+유료 심화 | 무료지만 범용 검색 — "선별"은 사용자 몫 |
| 아실·네이버페이 부동산 | 무료 | 아파트 중심, 경매는 부가 기능 | 주거 외 용도(상가·토지 등) 빈약 |
| 법원경매정보(공식) | 무료 | 원천 데이터 | 모바일 UX 취약, 필터 복잡 |

### 3.2 포지셔닝
경쟁자는 "많은 정보를 파는 도구"다. CrazyValue(미친가치)는 **"덜 보여주는 큐레이션"** 으로 초보·라이트 유저 공백 시장을 차지한다.
- 무료 + 무가입 + 모바일 온리 + 유찰 2회 이상만 — 이 4개 조합을 동시에 제공하는 서비스는 조사 범위에서 확인되지 않았다.
- 벤치마크 수용: 옥션원의 무료 검색 동선, 아실의 지도·시세 감각, 지지옥션의 데이터 신뢰 표기를 각각 참고한다(원안 "벤치마크" 요구의 수렴).

### 3.3 조사가 기획에 주는 함의
1. 원천 데이터는 법원경매정보 사이트가 유일한 공식 출처 — 수집 전략은 §5.4의 정찰 스파이크로 착수 시 확정한다.
2. 유료 서비스의 핵심 부가가치(권리분석)는 MVP 범위에서 제외하고, 법적 고지로 한계를 명확히 한다.
3. 무료 경쟁자 대비 차별점은 기능 수가 아니라 **선별 기준(유찰 2회 + 미친가치 픽) + 모바일 완성도**다.

## 4. 제품 사양

### 4.1 정보 구조 (IA) — 화면 4 + 시트 2
```
미친가치 CrazyValue (하단 탭 구성 단일 기준 = src/components/BottomTabs.tsx TABS)
├─ ① 홈(검색)     : 필터 3축 + 최근 본 물건 (진입 카드 2종은 §4.3-① 아래 철회 기록 참조)
├─ ② 리스트       : 10건 단위 카드 + 더보기 (홈에서 진입, /list)
├─ ③ 상세         : 물건 전체 정보 + 기일 이력 + 관심등록 + 공유 (/item/[id])
├─ ④ 관심함       : 등록 물건 D-day 정렬 + 상태 변화 추적 (/watch)
├─ 시트 A 온보딩   : 최초 1회 — 브랜드 설명 1장 + 관심 지역·금액대 설정(건너뛰기 가능)
└─ 시트 B 용어·고지 : 경매 용어 12개 풀이 + 미친가치 픽 기준 공개 + 법적 고지 전문 (/guide)
```
착수 이후 신설된 라우트(`/me` 내 설정 · `/refresh` 리프레쉬)는 이 기획 시점 IA에 없다 — 신설 사양과 계약은 `docs/TRACE.md`(N1) · `AGENTS.md` §1이 소유한다.

### 4.2 핵심 사용자 흐름
```
설치/접속 → (최초 1회) 온보딩: 미친가치란? 1장 → 지역·금액대 선택
→ 홈: 필터 3탭 (지역 → 금액 → 용도)
→ 리스트: 카드 10건 (픽 배지·할인율·D-day 즉시 인지)
→ 상세: 가격 구조 + 유찰 타임라인 + 원문 링크
→ 관심등록 → 관심함: D-day·재유찰 추적  /  공유 → OG 카드로 지인 상의
```
목표: **첫 화면에서 3번의 탭 안에 리스트 도달, 타이핑 0회.**

### 5.2 아키텍처
설계 원칙(기획 의도): **움직이는 부품 최소화** — 서버 코드는 상세 메타·OG 1곳뿐이고, 데이터 갱신 커밋이 곧 배포다.

### 5.3 데이터 모델 (`src/types/auction.ts` — zod 스키마)
```ts
AuctionItem {
  id: string            // "{법원코드}-{사건번호}-{물건번호}"
  court: string         // 담당 법원 (예: 수원지방법원)
  caseNo: string        // 사건번호 (예: 2025타경12345)
  itemNo: string        // 물건번호
  category: Category    // 아파트|다세대|단독다가구|오피스텔|상가|토지|공장창고|기타
  address: string       // 소재지 전체
  region: string        // 시·도
  district: string      // 시·군·구
  appraisalPrice: number  // 감정가(원)
  minPrice: number        // 현재 최저매각가격(원)
  priceRatio: number      // minPrice/appraisalPrice (수집 시 계산, 0~1) — 표시 할인율 = 1 − priceRatio
  failCount: number       // 유찰 횟수 (≥2)
  saleDate: string        // 매각기일 ISO
  saleTime: string        // 기일 시각
  courtRoom: string       // 경매법정
  deposit: number         // 입찰보증금(원문 기준)
  areaBuilding: number|null // 건물면적 ㎡
  areaLand: number|null     // 토지면적 ㎡
  photoUrl: string|null
  detailUrl: string       // 법원경매정보 원문 링크
  history: { date: string; minPrice: number; result: '유찰'|'변경'|'신건' }[]
  specialNote: string|null // 공고 비고
}
meta.json { crawledAt, totalCount, countsByRegion, nextUpdateAt, newCount }
```
- `newCount` = 이번 산출 id 중 직전 산출물에 없던 물건 수. 비교 기준이 불완전하면(첫 실행·지역 한정 수집) null이고, 화면은 그때 건수를 감춘다. `nextUpdateAt`은 화면에서 쓰지 않고 운영 판정용 기록 필드로만 남긴다.
- **미친가치 픽 판정은 파생 규칙**이라 스키마에 필드를 두지 않는다 — 판정식·부호 반전(필드는 비율, 화면 표시는 할인율) 규약은 `AGENTS.md` §2 도메인 불변식이 단일 기준이다.
- 파일 배치: `public/data/seoul.json` … 시·도 17개 분할 + `meta.json` (파일당 수백 KB 수준 유지)
- 이 스키마는 목데이터(Phase 1)와 실데이터(Phase 3)가 공유하는 **단일 계약**이다. 화면 코드는 데이터 출처를 모른다.

아래는 착수 시점 원안이다. 현행 파일은 슬롯 2개(일 full · 월~토 quick)·모드 분기·조기 종료 표면화·알림 이슈 중복 억제까지 확장돼 있다(TRACE.md "매일 갱신 전환" 절). 워크플로 이름 `weekly-crawl`은 바꾸지 않는다 — 이름을 바꾸면 등록된 스케줄과 런 이력이 끊긴다.

```yaml
# .github/workflows/crawl.yml — 착수 시점 전문
name: weekly-crawl
on:
  schedule:
    - cron: "0 18 * * 6"   # UTC 토 18:00 = KST 일요일 03:00 (원안 시각)
  workflow_dispatch:
jobs:
  crawl:
    runs-on: ubuntu-latest
    permissions: { contents: write }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm run crawl          # 검증 게이트 실패 시 여기서 중단 → 커밋 없음
      - name: commit data
        run: |
          git config user.name "crazyvalue-bot"
          git config user.email "actions@users.noreply.github.com"
          git add public/data
          git diff --cached --quiet || { git commit -m "data: weekly update $(date -u +%F)"; git push; }
```

- **DoD**: 원격 Actions 1회 성공 · 실데이터 zod 통과 · 스모크 실데이터 재통과
- 커밋: `feat: courtauction crawler + weekly cron` → 푸시

## 9. 배포·운영 규약
- **배포 경로 단일화**: `git push` → Vercel 자동 배포가 유일한 경로(Phase 0.6에서 확립, 최초 1회만 CLI `--prod`). 수동 업로드 금지.
- **데이터 갱신 = 배포**: 크롤 커밋이 곧 배포다. 별도 운영 작업 없음.
- **실패 격리**: 크롤이 실패한 날은 데이터 커밋이 없고, 앱은 직전 데이터+수집 시각 표기로 정상 동작한다. 다음 날 03:00 슬롯이 스스로 이어받는다.
- **관측**: 갱신이 매일이므로 점검 주기도 매일이다 — GitHub Actions 실행 이력(일 1회 성공 여부)과 워크플로가 여는 알림 이슈를 확인한다. 절차 단일 기준은 `docs/OPERATIONS.md`. **Vercel Analytics는 미도입**이라 관측 채널에 넣지 않는다(`package.json`에 `@vercel/analytics` 없음 — 현황은 `docs/TRACE.md` Phase 5.3).
